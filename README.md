# PHASE / 单环相位频闪调音器

可运行的 TypeScript + Vite + Web Audio + AudioWorklet + Canvas 原型。音频仅在浏览器内存中处理，无上传、录音存储、账号或云服务。范围为十二平均律 E2～E6（MIDI 40～88），识别边界额外放宽 60 音分。仅针对单音。

## 运行

需要 Node.js >= 22.18（测试使用 Node 原生 TypeScript 类型擦除）。

```sh
npm ci
npm run dev
```

打开终端显示的 `http://localhost:5173`。点击“开始调音”申请麦克风；“停止”关闭全部音轨、节点、AudioContext 和识别 Worker。可展开“内部信号测试”，选择合成输入后开始；它不申请麦克风且不发声。

```sh
npm test
npm run build
npm run preview
```

构建输出在 `dist/`，包含单独打包的 Worklet 和 Worker。依赖版本与 lockfile 均已固定。Windows 环境若默认 npm 缓存不可写，可使用 `npm ci --cache .npm-cache`。

## HTTPS 和手机

把完整 `dist/` 上传到支持 HTTPS 的静态站点根目录，开启有效 TLS 证书；JS 资源须返回 JavaScript MIME，不能把资源请求重写成 HTML。不需要后端、COOP/COEP 或 SharedArrayBuffer。若部署在子目录，先以 `npm run build -- --base=/tuner/` 生成对应路径。

手机访问电脑的 `http://192.168.x.x:5173` **不是安全上下文**，不能替代 HTTPS；手机测试请使用有效证书的 HTTPS 静态部署，或配置手机信任的本地 HTTPS 开发证书。不要绕过证书警告。尽量直接打开页面，嵌入 iframe 时还需要宿主允许 microphone 权限。这里提供部署说明，未进行线上部署。

## 两条独立处理路径

1. 麦克风连续样本 → AudioWorklet I/Q 混频、滤波、atan2 → 约 60 Hz 相位消息 → rAF 绘制。参考振荡器每个采样推进 `2π f_target / sampleRate`，所有振荡器、滤波及展开相位状态跨块保留。没有用实测频率或音分积分动画。
2. 同一连续流填满 4096 点非重叠窗口 → 三个缓冲区构成的有界可转移池 → 主线程转交 Pitchy Worker → 音高、clarity 与 RMS。48 kHz 下约 11.7 帧/秒，44.1 kHz 下约 10.8 帧/秒。Worker 延迟耗尽缓冲池时，丢弃识别样本；连续相位处理不停止。数字 Hz 和音分来自这一路，采用 0.4 系数指数平滑；不会冻结任何音分区间。

已核对 [Pitchy 官方 README](https://github.com/ianprime0509/pitchy#readme) 和 [4.1.0 npm 包](https://www.npmjs.com/package/pitchy/v/4.1.0)：使用 `PitchDetector.forFloat32Array(4096)` 与 `findPitch(input, sampleRate)`，返回 `[frequency, clarity]`。Pitchy 在 Worker 中运行，避免在实时音频线程执行 FFT 或其临时数组分配。

## 解调参数和映射

对余弦输入，`I = LPF(x cos θ)`，`Q = LPF(-x sin θ)`；`atan2(Q,I)` 的正向漂移对应输入偏高。DSP 按最短角差展开 ±π 边界。Canvas 正角度为顺时针。

每个正交通道使用四个相同的一阶低通串联（四阶，**不是 Butterworth**），每级系数 `α = 1 - exp(-2π fc / fs)`，`fc = min(30 Hz, 0.12 × f_target)`。总响应近似 `|H(f)| = [1+(f/fc)²]^-2`，总 -3 dB 约 `0.435 fc`。E2 时每级 fc≈9.89 Hz、总 -3 dB≈4.30 Hz；A2 为 13.2/5.74 Hz；A4 及以上为 30/13.05 Hz。

固定目标后 400 ms 内不显示可信条纹。E2 的四阶单位阶跃在此时剩余误差约 4×10^-8；真实拨弦、自动选音和识别延迟仍会更长。低频群延迟近似 `4/(2π fc)`，E2 约 64 ms，A4 约 21 ms。同频 E2 的混频镜像在 2f≈165 Hz，滤波抑制约 98 dB；E2 二次谐波混频后的差频≈82 Hz，约 74 dB。四阶滤波让小频差响应和镜像抑制兼顾，代价是启动稳定时间。

可信频差限制为 `|f_est - f_target| <= 0.65 fc`：E2 约 ±6.43 Hz，A2 ±8.58 Hz，A4/E6 ±19.5 Hz。超出时继续显示可靠的数字读数，隐藏条纹并提示靠近目标。这意味着高音区自动选音后仍可能需要先粗调。Pitchy 仅参与门控和选音，不参与相位位置计算。

单环有 **12 个重复扇区**，屏幕角度为连续跟踪的解调相位 `/ 12`。解调相位一圈只移动一个扇区间距（30°），不是屏幕几何一圈；+1 Hz 为每秒一个扇区，连续标记的位置需 12 秒转一圈。相同重复扇区在一周期后视觉等价。rAF 对实际相位作短程插值，不外推；低帧率或长时间卡顿仍可能产生视觉混叠，不能拿肉眼转速当精密频差计。没有独立泛音环，也不声称复现任何商业专有算法。

## 可靠性、选音和生命周期

- 相位门槛：稳定 400 ms、RMS > 0.002（约 -54 dBFS）、解调幅值 > 0.0015、解调幅值 / (√2 RMS) > 0.08。
- Pitchy clarity >= 0.9、RMS > 0.002、音高在扩展范围内。只有两条路径同时有效、位于可信频差范围、相位消息不超过 150 ms、识别消息不超过 350 ms，才显示条纹。噪声、静音和基频缺失不能被显示成“已调准”。UI 不提供“调准”死区。
- 自动选音连续 3 帧确认；距离当前目标不超过 65 音分时保持原目标；一八度或更大跳变需连续 6 帧。它降低跳动，不是可靠的缺失基频重建或八度纠错器。
- `f_target = A4 × 2^((midi - 69)/12)`。A4 限制 430～450 Hz，步长 0.1 Hz。自动目标确定后始终为标准频率，不跟随实测值漂移。手动模式覆盖全部 49 个半音，越界选项禁用；换八度时必要时夹到 E2/E6。
- 锁定保持当前标准目标，解除恢复所选模式；改变目标/A4 会清空数字平滑、递增配置版本、重置振荡器及滤波状态、丢弃旧版本消息。
- 请求关闭回声消除、自动增益和降噪，但设备可能不遵从。输出全部为零，Worklet 连接 destination 仅维持处理，不回放输入。
- 停止即停轨并断开节点；取消待授权启动时，迟到的媒体流也立即释放。暂停/中断清空读数并提供恢复按钮；页面切回尝试恢复并重新稳定；pagehide 停止，设备音轨 ended 清理。底层噪声/音频处理改变会影响结果。

## 验证与限制

见 [TESTING.md](TESTING.md) 的执行记录、真实数值及人工步骤，完整自动测试输出为 [test-results.txt](test-results.txt)。合成信号共用采样时钟只能验证算法，不能证明麦克风设备的绝对准确度；不宣称 0.1 音分测量精度。

后续优先工作：真实吉他与不同手机的低频响应、静音阈值调校、缺失基频/八度候选比较、实际音频时钟外部校准、低端设备的调度负载与卡顿测试。多环应分别按各谐波独立解调后再增加。

主要文件：`src/dsp.ts`（正式 DSP 和目标选择），`src/audio-worklet.ts`（连续采样、缓冲池），`src/pitch-worker.ts`（音高识别），`src/session.ts`（资源生命周期），`src/main.ts`（交互/Canvas），`tests/`（复用正式 DSP 的测试）。
